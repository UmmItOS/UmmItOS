# Shell features

## Screenshots

`Screenshot` has two overlay modes, drawn by one overlay (`ScreenshotWindow`): `region` (Shift+Print, drag; the wheel zooms) and `window` (Super+Print or Super+Shift+W, pick one). Print takes the focused screen at once with `grim` (`screenNow()`), with no overlay, since there is nothing to pick. The overlay freezes the screen with a `ScreencopyView` captured once on open, blurs it, and hangs the selection from the screen corners on tendrils that trail the pointer on springs (except in region mode, where the corners are the pointer). A region or screen shot is taken with `grim` only after the overlay has left, so the overlay is never in it. A window shot does not use `grim`: it captures the window's own surface (`HyprlandToplevel.wayland`) off screen, clips it to Hyprland's corner radius and saves it with `grabToImage`, which keeps transparency. Files go to `HYPRSHOT_DIR` (the name predates the shell) and onto the clipboard. From Print until just after the capture, `Screenshot.holding` pauses the toast and copy-pill timers and keeps the notification panel open when the overlay's keyboard grab clears its focus grab, so whatever was on screen at Print is in the picture.

## Screenshot gallery

Super+F (`Gallery` singleton, `screenshot/GalleryWindow.qml`) shows every picture of the screenshot folder, newest first, as a full-screen grid whose cards fly in from scattered spots (PageUp, PageDown, Home and End jump). The mouse wheel glides (`GalleryWindow.nudge()`, longer when notches come fast, a touchpad keeps Flickable's own momentum), the ends give and spring back, the top and bottom fade out only where there is more, and a thin indicator shows while it moves; Enter or a click copies the picked one to the clipboard again and closes. The folder is Settings → Screenshots (`Settings.shotDir`, saved in `~/.config/ummitos/screenshot.conf`), which `Screenshot.dir` follows; empty means `HYPRSHOT_DIR`, else `~/Pictures/Screenshots`. Thumbnails decode at the cell's width, not full size. Typing searches the text inside the pictures: `script/misc/ocr-index.sh` reads each one with tesseract (`eng+chi_tra`) into `~/.local/state/ummitos/ocr.db` (mode 600; one `LIKE` query, since FTS tokenizers split Chinese badly), the gallery starts it on open (a `flock` keeps it to one run, niced) and every new screenshot is read when it is saved.

## Health check

Super+H (`Doctor` singleton, `doctor/DoctorWindow.qml`) runs `script/misc/doctor.sh` and prints its lines as they arrive, like a package install: the repo and its submodules, whether the shell is linked to the repo and loaded without errors, whether `~/script` and your `shortcuts.lua` have what the repo has, whether Hyprland accepts its config, the packages, the commands the shell calls, the input method (fcitx5 running, its UmmItOS theme chosen), the dotfiles the repo ships (differences only, never overwritten), the autostart entries and the services. One shell start in `Theme.duration.doctorStart` runs it quietly and sends a notice only for a failure. `--fix scripts` is the only thing it repairs (the repo is the scripts' source); your Hyprland config is never touched, a missing bind is only reported. **A new check is a function in `doctor.sh` that calls `say ok|warn|fail GROUP TITLE DETAIL`.** After a `git pull` on another machine, open it first.

## Security notices

`script/misc/advisories.sh` prints a notice box of the five newest items of the Arch news feed (`archlinux.org/feeds/news/`) for the top of `update.sh` (the rows come from `sel_info` in `_tui.sh`), and with `--notify` sends each new alarming item from the last week once as a critical notice; the shell's `Updates` service runs that after login and every 6 hours. The mailing lists sit behind Anubis, so nothing reads them by script. Everything that arrives is stripped of control characters and shown as plain text.

## Wipe

Settings → Anti-forensics (`settings/WipePage.qml`) lists what the desktop remembers, per kind, with the file paths and sizes found live (`script/misc/wipe-traces.sh --list`), and overwrites then deletes the ticked ones (`shred -n N -z -u`). The shell forgets the in-memory copies first (`FileChanges.forget()`, `Launcher.forgetLaunches()`, `forgetClipboard()`), or it would write them back. A new kind of stored trace is a new `wipe_<name>` function in the script plus a card in the page. The page says plainly that copy-on-write file systems (btrfs) and SSDs can keep old copies; **never run the script without `--list` to test it against the real home folder**: it deletes for good.

## Switcher and overview

`Switcher` is both Alt+Tab and the GNOME-style overview (`switcher/HotCorner.qml`, a 3px Top-layer window per screen). `Switcher.overviewing` marks the overview; only it gets the zoom-out on open, the corner rings and the stronger selection, so Alt+Tab keeps its look. Every close zooms into the chosen card. For a sharp zoom the overview first takes a full-resolution `grim -t ppm` picture and lays it over the card; previews are captured once at native size and drawn through a `ShaderEffectSource { mipmap: true }`. Never resize a live `ScreencopyView` (changing `constraintSize` mid-capture killed the shell).

## Lock screen

`Lock` (singleton) and `lock/LockScreen.qml`: a `WlSessionLock` with one `WlSessionLockSurface` per screen, drawing `LockContent`. The desktop's weather card sits top left and, while music plays, its now-playing card at the foot with its controls under the pointer (both `wanted: true`, so the desktop switches do not hide them, and `fadeSelf: false`, so they follow the lock's own fade frame for frame instead of chasing it). While music plays, `lock/LockSpectrum.qml` draws Cava's bands behind the clock, mirrored from the middle, tapered at the ends and coloured from the accent; it reads `Cava.levels`, which already runs because the lock's now-playing card counts itself in `Players.cardViewers`. `ipc call lock preview` shows the same content in an ordinary window, which is how the look is worked on; never save a lock file while really locked, since a reload recreates the lock. The password goes through a `PamContext` whose stack lives in the shell (`lock/pam/password`, `pam_unix`), so no `/etc/pam.d` file is needed. Before locking, each screen is captured with `grim -t ppm` into `$XDG_RUNTIME_DIR/ummitos-lock` (PNG encoding was ~0.6s and read as lag); the lock fades in from that picture and fades back to it before releasing, because a lock surface is opaque and the desktop cannot show through. A hot reload while locked fails closed: Quickshell hands the live session lock to the new instance only when the `WlSessionLock` has a matching `reloadableId`, and this one has none, so the old lock is destroyed still locked (an empty lock screen, recovered from a TTY). **Never give the lock, or anything above it, a `reloadableId`**: the new instance starts with `locked: false` and would release the lock. hypridle holds suspend until the lock is up only because `inhibit_sleep = 3` (`configs/hypr/hypridle.conf`; the default waits only for hyprlock), and logind caps that hold at `InhibitDelayMaxSec`, 5 s by default. `misc:allow_session_lock_restore` is on, so if `qs` dies while locked: switch to a TTY, start `qs -c ummitos -d` in the session's environment, run `qs -c ummitos ipc call lock lock`, go back and unlock.

## Picture converter

`Convert` (singleton) and `convert/ConvertWindow.qml`, styled after GTA V on purpose, with its own `Theme.gta` palette and sizes like `Theme.sao`. Pictures arrive only by drag and drop: the window covers the screen, but its input mask is the wheel alone, so a picture can be dragged in from the windows around it. Its keyboard focus is `OnDemand`, never `Exclusive`, because while a layer holds the keyboard exclusively Hyprland lets no other surface start a drag. `script/misc/img-convert.sh` writes each picture beside its original (a web link is fetched into Downloads, and an unwritable folder falls back to it). It takes the type from `file`, never from ImageMagick's own sniffing, which would also run its script and vector decoders, then reads with only that decoder. The banner title is fixed artwork made with Typodermic's Pricedown (`convert/mission-*.png`, white so the colours stay tokens): the font's licence allows shipping a picture made with it, not the font itself. The `mission-passed` and `mission-failed` sounds link to `/dev/null`; the game's audio is not ours to ship, so a user links their own.

Test a drop for real with `ydotoold -p <sock>` (the user can write `/dev/uinput`) and a small `qs -p` drag source. Before moving, check from the source's log that the press reached it, or the drag lands in whatever window is behind it. And never `pkill -f` a pattern that also appears in the running command, or it kills its own shell.

## Display chooser

Super+P or a right-click on the desktop ("Displays…", beside "Wallpaper…" and "Settings" in `background/DesktopMenu.qml`) opens `displays/DisplaysWindow.qml`, a Win+P style chooser over the `Displays` singleton, which reads `hyprctl -j monitors all`, derives the mode (single, mirror, extend, second) and applies it at runtime only with `hyprctl eval` `hl.monitor` calls, never writing a config file; every change keeps each output's current mode and scale, waits `Theme.duration.displayConfirm` for Keep (only the Keep button keeps) and reverts to the snapshot on its own (also when the panel closes or a screen is plugged in or out), the revert skipping outputs that are gone and never switching every one off; the revert's Lua is also saved in `$XDG_RUNTIME_DIR/ummitos-displays-revert.lua` and a detached `sh` watchdog runs it after the countdown if the file is still there and no newer change refreshed it, so a reload or crash cannot strand a change (the shell also runs a stale file at start), and each call states `disabled` and `mirror` because Hyprland merges a rule into the old one. The desktop right-click menu (`background/DesktopMenu.qml`) also holds a "Show on desktop" group of switch rows for the weather card, the now-playing card, Activate Linux and the FPS counter; they call the same `Settings` setters as the Settings pages, so the choice lands in `desktop.conf`, and they keep the menu open.

## Heavy process warning

`script/misc/proc-hogs.sh` is a one-shot sampler (two reads of `/proc/*/stat` and the amdgpu `drm-engine-gfx` fdinfo, 1 s apart, one awk pass) that prints up to 5 `pid<TAB>cpu<TAB>gpu<TAB>name` lines, CPU as a share of the whole machine. The `ProcWatch` singleton (`services/`) runs it every `Theme.duration.hogPoll` while `Settings.hogWarn` is on (Settings → Misc, `hog=` in `desktop.conf`), counts a streak per pid, and after `Theme.hog.samples` samples above `Theme.hog.cpu` or `Theme.hog.gpu` sends one notice per episode and shows `bar/HogWatch.qml` beside `FileWatch`. It only warns, never kills. It polls always, unlike `SysInfo`, because a monitor that waits for a viewer would miss the thing it is for. Only the user's own processes show GPU use, and the compositor can itself read as a GPU hog.

## Wallpaper browser

There are two pickers over the one `Wallpapers` singleton, each built for one kind of input. Alt+W (`wallpaper toggle`, `pickerOpen`) opens `background/WallpaperPicker.qml`, the keyboard carousel. A right-click on the desktop, then "Wallpaper…" (or `wallpaper browse`, `browserOpen`), opens `background/WallpaperBrowser.qml`, the mouse drawer on the right edge: folder chips (`Wallpapers.folders`) over a two-column grid of named thumbnails, with no scrim so the desktop shows the preview undimmed. Hovering a picture previews it on the desktop behind the panel, a click sets it, and Escape or an outside click restores the previous wallpaper. Opening one picker closes the other. The verify stack has no `~/.wallpaper`, so make a few pictures in its fake HOME (`magick -size 1920x1080 gradient:red-black $STACK/home/.wallpaper/A/x.jpg`) before testing either picker.
